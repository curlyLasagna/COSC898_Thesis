1. Executive Summary

Across automated agentic benchmarks for deterministic environment generation (via the course-flake-generator skill), a substantial disparity in tool usage behavior was observed between frontier proprietary models and medium open-weight models. In trial run 20261101_161538, the GPT-OSS 120B model queried the NixOS Model Context Protocol (MCP) server only 6 times across 3 trials (out of 41 completed trials), accounting for just 1.02% of all executed tool calls. By contrast, the proprietary frontier baseline (Gemini) in run 20260929_001840 executed 146 MCP tool calls across 39 trials (18.5% of total tool calls).

A systematic review of the trajectory step logs and internal chain-of-thought (thinking) transcripts across all 41 samples identified a primary cognitive failure mode: a semantic false-negative trap caused by protocol primitive confusion between MCP Resources and MCP Tools. In 58.5% of trials, GPT-OSS attempted to discover server capabilities via list_resources. Because the NixOS server strictly exposes tools (callable RPC functions) and zero static data resources, the harness responded that no resources were present. The model misinterpreted this negative confirmation as an indication that the MCP server itself was offline or empty, subsequently abandoning MCP in favor of native CLI search or memorized package names.

3. Qualitative Root Cause Analysis

Transcript examination reveals five interconnected factors that suppressed MCP utilization in the weaker model:

3.1. The Resource False-Negative Trap (Protocol Primitive Confusion)

The Model Context Protocol specification cleanly differentiates between resources (passive, readable data URIs) and tools (executable actions with schemas). The mcp-nixos server provides package resolution through two executable tools: nix (search, info) and nix_versions. It does not publish any readable resources.

In 24 out of 41 trials (58.54%), GPT-OSS’s first action was an exploratory probe to verify server presence using the resource discovery endpoint: 

{"name": "list_resources", "args": {"ServerName": "\"nixos\""}}

The AGY harness returned the standard protocol response: 

MCP server nixos does not have any resources

Due to weaker reasoning capabilities, the open-weight model conflated the absence of static resources with server non-availability. In transcript after transcript, the model's thinking logs show it immediately deducing that the server was broken or unavailable:

task_12 / sample_01 (Step 3):
"According to skill, need to check MCP server for package resolution. List resources shows none. So no mcp-nixos. We'll need to use Nix CLI to search for MySQL package."

task_12 / sample_02 (Step 3):
"According to skill, we need to determine if mcp-nixos available. We listed resources, none. So need to fallback to Nix CLI search. We'll need to search for mysql packages."

task_04 / sample_00 (Step 7):
"Use MCP nixos if available; but list_resources showed none, so MCP isn't offering packages directly. Fall back to Nix CLI search."

task_00 / sample_01 (Step 3):
"Must use mcp-nixos if available; we saw no resources, but that's not needed. We can use Nix CLI via run_command to search for openjdk17 package name..."

This single false-negative inference accounted for the immediate termination of MCP workflows in over half the benchmark.

3.2. Cognitive Load of Meta-Tool Proxying (call_mcp_tool)

Frontier systems handle deep JSON nesting and multi-layer tool proxying with ease. In the AGY test harness, MCP tools are not declared as top-level function signatures (e.g. mcp_nixos_nix(...)) due to lazy loading; instead, they require invoking a meta-wrapper: 

call_mcp_tool(
  ServerName="nixos",
  ToolName="nix",
  Arguments="{\"action\":\"search\",\"query\":\"dotnet-sdk\",\"type\":\"packages\",\"channel\":\"stable\",\"limit\":5}"
)

This requires the agent to stringify nested JSON inside a structured tool-call object. In the GPT-OSS run, over 80 agent turns resulted in formatting crashes (model output error: model output must contain either output text or tool calls) because the model attempted to write shell commands or raw JSON fragments into its internal chain-of-thought instead of generating valid function call objects.

3.3. Permissive Skill Fallback as an Escape Hatch

The benchmark instruction set (course-flake-generator) includes an explicit fallback clause in Step 2:

"Nix CLI Mode / Fallback: If mcp-nixos is not configured or unavailable... use the native Nix CLI via run_command to discover and verify package attributes (nix search --extra-experimental-features 'nix-command flakes' nixpkgs <candidate_tool>)."

Because the model had already misdiagnosed the MCP server as absent (Section 3.1), this clause provided a sanctioned alternative. The agent immediately routed its search requirements through run_command, performing 81 CLI searches across 24 trials rather than attempting any recovery of the MCP interface.

3.4. Prompt-Level MCP Disabling in Task 01

In Task 01 (Flutter SDK development environment), the prompt passed to the agent explicitly included: 

(Note: NixOS MCP server is disabled; use the Nix CLI to discover and verify package attributes.)

This prompt condition forcibly prevented the agent from attempting any MCP queries in Task 01 (all three samples), resulting in 27 manual nix search invocations through the shell.

3.5. Parametric Memory Bias (Zero-Search Synthesis)

In 14 trials (34.15% of the run), GPT-OSS executed neither an MCP call nor a native nix search command. For common stacks with standard package naming conventions—such as Node.js LTS (nodejs_20), Python 3.12 (python312), Rust (rustc, cargo), Go (go_1_22), and GCC (gcc)—the model relied entirely on its internal pre-training weights and the skill's template (flake-devshell.template.nix), bypassing external verification entirely.

4. Examination of the Three Outlier Trials

In only 3 trials did GPT-OSS 120B successfully issue calls to call_mcp_tool. Analyzing how these trials bypassed the typical failure modes provides valuable insight:

  1. task_13 / sample_00 (MySQL Workbench): At Step 1, the model did not attempt any reconnaissance with list_resources. Instead, recognizing that GUI packages in Nixpkgs often have non-standard names, it immediately formulated a direct search query via call_mcp_tool (query: "mysql-workbench").
  2. task_08 / sample_01 (.NET SDK): At Step 3, the model called list_resources and received the empty response. Unlike other samples, its chain of thought explicitly reasoned through the protocol distinction:

    "We need to check if mcp-nixos is available; the config shows nixos server, but resources list empty. Still we can use MCP tool? There is no tool schemas listed but the mcp server has lazy tools 'nix' and 'nix_versions'. So we can call them via call_mcp_tool."

    It immediately called call_mcp_tool for dotnet-sdk at Step 5.
  3. task_04 / sample_02 (Clang / CMake / Make): The model initially fell into the list_resources trap at Step 7 and attempted manual git and shell commands. However, around Step 30, it encountered ambiguity regarding whether clang++ was part of clang or a separate package, and re-read the skill documentation. Over Steps 33–43, it executed 4 sequential MCP package searches (clang, cmake, make, and gnumake).

5. Architectural Recommendations for Benchmark & Harness Design

To ensure consistent evaluation of tool-augmented agents—especially open-weight models that exhibit lower tolerance for multi-layered indirection—the following harness and prompt modifications are recommended:

  • First-Class Function Declarations: Avoid nesting lazy MCP tools inside generic proxy dispatchers (call_mcp_tool with stringified JSON). Inject tools directly into the model's function calling schema (e.g. mcp_nixos_search).
  • Informative Protocol Responses: When an agent calls list_resources on a server that only registers tools, the harness response should clarify capability status: e.g., "Server 'nixos' publishes no resources, but exposes the following tools: ['nix', 'nix_versions']."
  • Refined Skill Guardrails: Revise skill instructions from "Check if .agents/mcp_config.json is present and tools are available" to explicit instructions on invoking the tool directly, avoiding ambiguity between resource inspection and tool invocation.
