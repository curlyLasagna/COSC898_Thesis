\chapter{Conclusion}\label{conclusion}

\section{Summary of Contributions}

This thesis addressed the critical challenge of development environment inconsistency in computer science higher education by investigating an AI-assisted synthesis framework for declarative Nix Flakes. For decades, academic institutions have struggled with the ``works on my machine'' dilemma, forcing instructors and students to squander instructional time troubleshooting platform-specific dependency conflicts. Although several technologies can isolate development environments, reproducibility is only meaningful when an environment can be recreated on a machine that does not inherit the authoring host's packages, configuration, or build cache. Purely functional package management via Nix supplies a strong basis for that goal, but its steep learning curve and non-intuitive syntax may discourage classroom adoption.

To resolve this dilemma, we designed, implemented, and evaluated an automated environment synthesis pipeline that leverages agentic Large Language Models. By introducing a specialized custom agent skill (\texttt{course-flake-generator}), our architecture transforms general-purpose AI assistants into domain experts capable of generating \texttt{flake.nix} configurations from natural language assignment descriptions. To eliminate package hallucinations, the pipeline integrates a Model Context Protocol (\texttt{mcp-nixos}) server that queries live NixOS package registries in real time. Crucially, the functional purity of the Nix evaluation engine provides a closed-loop deterministic validation mechanism, enabling the agent harness to autonomously diagnose compiler stack traces and self-correct invalid specifications.

\section{Synthesis of Research Questions}

The empirical findings of this research provide definitive answers to the three core research questions:

\begin{itemize}
	\item \textbf{RQ1 (Agentic Synthesis Accuracy):} AI agents can accurately infer system-level dependencies and generate valid \texttt{flake.nix} environments when augmented with specialized skills and real-time registry tools. While baseline zero-shot prompting frequently triggers regression to imperative package managers (such as Homebrew on macOS), structured agent skills guide models to achieve over 85\% synthesis accuracy on systems programming assignments. The closed-loop error recovery mechanism proves vital in resolving upstream package deprecations and domain-specific native library bindings.
	\item \textbf{RQ2 (Clean-Container Reproducibility):} A locally valid flake is not, by itself, evidence that the environment will work for a student who lacks the authoring machine's state. RQ2 therefore replays every RQ1-passing flake and lock file in a fresh, unmounted Nix Docker container. Each replay evaluates the flake, activates its development shell, verifies the required executables, and runs curated headless task commands. The resulting clean-container reproduction rate, together with classified failures in evaluation, activation, dependency availability, or task execution, provides a stricter measure of reproducibility than a single host-side validation pass.
	\item \textbf{RQ3 (Classroom Deployment Reliability):} A valid and reproducible flake does not, by itself, establish dependable classroom deployment. RQ3 evaluates the operational constraints that affect reliability, distinguishes fixed-environment activation from maintenance activity, and treats mitigation choices as explicit availability and trust trade-offs. A classroom deployment is dependable only when it meets its setup-time budget while preserving an approved supply-chain trust boundary.
\end{itemize}

\section{Limitations and Future Work}

While this work demonstrates the viability of AI-assisted declarative environment synthesis, several avenues remain for ongoing research and refinement. The input data generated for testing was simple enough for Gemini models to succeed in the experiment condition where the Nix MCP server was withheld; it therefore does not establish the value of MCP retrieval for more difficult or less conventional requirements.

Although flakes guarantees reproducibility, the longevity of flakes could be a concern. A semester long study on real student machines would be interesting

Second, while the \texttt{mcp-nixos} server provides current package metadata, further research should compare experimenter-controlled MCP access across tasks with obscure, recently changed, or platform-specific dependencies. Such a study could identify when MCP retrieval improves synthesis success or reduces diagnostic iterations relative to native Nix CLI discovery alone.

The 5 hour token limit imposed by AI providers limits the number of runs

Finally, the clean-container replay evaluates a Linux Nix container and deliberately excludes graphical workflows, interactive credentials, and persistent service administration. Future work should repeat the protocol across Linux, macOS, and Windows hosts; incorporate controlled tests for editors and services; and measure the RQ3 availability conditions across multiple course terms and package-set revisions.

By bridging artificial intelligence with a purely functional development environment, computer science education can bypass the fragility of manual configuration in favor of reliable, and deterministic reproducibility.
