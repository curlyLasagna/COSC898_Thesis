Inconsistent development environments pose substantial friction for software engineers and development teams, frequently consuming days of onboarding time and shifting engineering focus from feature delivery to environment debugging. In computer science education, this challenge is acutely amplified. When students must imperatively configure their personal machines for diverse coursework, valuable lecture and lab hours are often sacrificed to troubleshooting dependency conflicts. The myriad combination of student hardware, operating systems, and local configuration states turns instructors and teaching assistants into ad-hoc technical support providers, creating severe barriers to student engagement and learning.

This thesis proposes an automated workflow that leverages agentic large language models (LLMs) to synthesize reproducible development environments using Nix Flakes from instructors' natural language requirements or to infer requirements from a project's source code. Because environment synthesis is a recurrent task across semesters, we designed and implemented a specialized custom agent skill that provides an agent with domain-specific flake templates, structured metadata, and automated validation heuristics to repeatedly perform the task with the proper context. To prevent package hallucination within the massive Nixpkgs ecosystem, the agent reaches out to a Model Context Protocol (MCP) server to retrieve real-time package metadata and configuration schemas directly from NixOS search indexes. Synthesized flakes are verified through a deterministic evaluation pipeline using native Nix tooling, enabling the agent to autonomously interpret evaluation error traces to self-correct invalid specifications. Furthermore, this study evaluates student onboarding ergonomics by comparing declarative environment activation via Nix Flakes against traditional imperative installation, measuring the time required to get students up and running with a functional development environment alongside subjective cognitive effort captured from student feedback to determine whether introducing Nix into a course is worthwhile in practice. Finally, this thesis examines the security implications of using nix, analyzing how binary caches can serve as a potential attack vector and evaluating the security measures in place both to secure binary caches and to mitigate supply-chain attacks.
